# ADR-0009：升级与修复授权分离

- 日期：2026-08-09
- 状态：已接受
- 相关：ADR-0004（分支恢复与脏策略）、ADR-0007（最小权限运行账户）、全局 AGENTS.md 授权边界、各组件运行手册既有边界

## 背景

控制平面触发的修复会话把“恢复既有服务”当作目标，而“顺手升级”很容易被当作修复的一部分混入候选分支。修复（fix/repair）以恢复既有契约与既有行为为边界；升级（upgrade）会改变版本、接口、依赖或配置契约，属于独立变更。二者混同会带来三类风险：

1. 未经单独批准的升级随修复分支合入，扩大变更面；
2. 升级失败时回退范围被放大，且可能覆盖修复成果；
3. 运行手册中声明的边界被静默拓宽，后续修复默认携带越权变更。

## 决策

- **修复 = 授权范围**：被授权的修复任务只覆盖使系统回到既有契约所需的最小变更（按既有版本重建、恢复配置、回滚到上次已知良好状态、执行运行手册白名单内的自愈命令）。修复授权不隐含版本、接口或依赖升级的许可。
- **升级 = 独立变更，需单独批准**：任何改变版本号、公开接口、依赖大版本、数据库 schema、镜像 tag 或配置契约的变更，即使与当前修复直接相关，也必须作为独立变更单独申请批准，并保留独立的批准记录。
- **以运行手册既有边界为准**：各组件运行手册（RUNBOOK）中已声明的允许操作与禁止操作是授权范围的唯一事实来源；与手册冲突的修复动作同样需要单独批准，不得以“这是修复”为由越过手册边界。

## 边界示例

允许（修复授权范围内）：

- 按既有版本重建损坏容器、重启服务并等待健康；
- 恢复被误改的配置文件、回滚到上次已知良好状态；
- 执行运行手册白名单内的只读诊断与自愈命令；
- 保持既有依赖锁定的补丁级修复（不改变锁定版本）。

不允许（默认需单独批准）：

- 升级依赖大版本、更换镜像 tag、迁移数据库 schema；
- 改变公开接口或配置契约；
- 将本 ADR 未列出的新操作加入运行手册。

## 验证

- 候选分支 diff 中不出现升级类变更；评审时核对升级项是否有独立批准记录。
- 运行手册边界条款与本 ADR 语义一致，无静默拓宽。

## 回退

无代码回退。若发现升级类变更混入修复分支，将对应提交移出分支并重新走独立批准流程，修复分支保持可合并状态。
