# 研究记录：计划任务迁移为正式 Windows 服务（价值评估）

- 日期：2026-08-09
- 状态：研究（候选），未决策执行

## 现状与问题

控制平面由计划任务 `ControlPlane`（开机触发，失败最多重启 3 次）经 `Start-ControlPlaneHidden.vbs` 隐藏窗口启动。批次 2 实施后已具备：PID 文件防双实例、`taskkill /T /F` 进程树终止、/live 与 /ready 探针。遗留问题：

1. 停止路径不投递 SIGTERM：VBS 用 `Run(..., True)` 同步等待，停止依赖 taskkill 硬杀（新代码已提供确定性手段，但无优雅信号路径）。
2. 无系统级日志/崩溃转储管理；计划任务“失败重启 3 次”无背压语义。
3. 运行账户为交互用户（见 ADR-0007），非最小权限。

## 迁移价值

| 维度 | 计划任务（现状） | 正式 Windows 服务（sc.exe / NSSM / 自建） |
|---|---|---|
| 开机顺序与依赖 | 无序，易与 Docker 未就绪竞争 | 可声明依赖（Docker）与延迟 |
| 崩溃恢复 | 简单计数重启 | Restart 服务配置 + 背压/退避 |
| 优雅停止 | 无信号 | 可接 Service Control 事件 |
| 日志 | 自定义文件 | 可与 EventLog/统一日志集成 |
| 权限 | 用户会话权限 | 可配置低权限账户 + 服务账户 |
| 运维可见性 | 任务状态 | 服务状态 + SC 查询 |

## 成本与风险

- 迁移本身是独立变更：需要服务安装（管理员）、运行账户调整（ADR-0007）、启动脚本改造、任务停用与回滚验证。
- Windows 服务对“隐藏窗口 + 长驻 Python（uvicorn）”支持良好，但需处理工作目录、环境变量与凭据（服务账户无法访问用户 Credential Manager 条目——需要凭据代理调整）。
- 与飞书 gateway 通知链路无关，但控制平面依赖的凭据存取（`codex-credential-broker.ps1`）按用户凭据库设计，低权限账户下需改为服务账户凭据或 Bitwarden 直连（另行评估）。

## 建议

分两步：
1. 近期（批次 2 内已具备）：`taskkill /T /F` 停止脚本 + PID 单实例 + /ready 探针，保持计划任务形态；把停止改为确定性树终止（README 已记录）。
2. 中期（需单独授权窗口）：结合 ADR-0007 低权限账户，评估 NSSM/`sc.exe` 迁移；前置条件是 Credential Manager 存取方案落定。

## 结论

迁移有净价值但非紧急；当前计划任务 + 批次 2 机制（PID、树终止、探针、白名单 sudoers）已覆盖主要风险。迁移在低权限账户方案实施后作为独立窗口评估。

## 2026-08-10 事故后补充

一次硬终止暴露出仅有开机触发器、Task Scheduler 历史关闭、启动器不保留退出证据的共同盲区。ADR-0011 已在不改变运行账户的前提下补充直接由任务持有的 PowerShell 监督器、独立 watchdog、Operational 历史和陈旧运行记录收敛；VBS 中间启动层已移除，避免任务显示 `Ready` 时监督器与 Python 仍成为孤儿进程。该改动降低当前计划任务方案的恢复时间，但不替代本记录中的正式 Windows 服务迁移评估。
